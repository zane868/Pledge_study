## 3. 本次改动

### 3.1 合约 `pledgev2/contracts/pledge/PledgePool.sol`

新增三个强制接口，只跳过时间校验，状态机、计价、兑换和多签校验不变：

| 接口 | selector | 跳过的校验 | 要求的状态 |
|---|---|---|---|
| `forceSettle(uint256)` | `0xb17f1983` | `block.timestamp > settleTime` | MATCH |
| `forceFinish(uint256)` | `0xb6b21b96` | `block.timestamp > endTime` | EXECUTION |
| `forceLiquidate(uint256)` | `0x6ca14389` | `block.timestamp > settleTime` | EXECUTION |

实现方式：把 `settle`、`finish`、`liquidate` 的主体移到 `_settle`、`_finish`、`_liquidate`。
时间校验留在外部接口，强制接口直接调内部函数，业务逻辑只有一份。

`_finish` 的计息时长改为 `endTime > settleTime ? endTime - settleTime : 0`，避免 SafeMath 下溢。
`_liquidate` 没有改这处，因为 `createPoolInfo` 已保证 `endTime > settleTime`。

`forceLiquidate` 有实际用途：`forceSettle` 能让池在 settleTime 之前进入 EXECUTION，
此时常规 `liquidate` 会被时间校验拦住。

## 5. 关键机制说明

### 5.1 多签授权

- `createApplication(to)` 生成申请，msghash = `keccak256(abi.encodePacked(申请人, to))`，不保存 calldata。
- 管理员调用 `signApplication(msghash)`，签名数达到门槛后 `getValidSignature(msghash, 0) > 0`。
- Pool 上带 `validCall` 的函数校验 `keccak256(msg.sender, pool)` 是否已批准，所以必须由申请人本人发交易。
- **授权不会被消耗。** 一旦批准，申请人可以无限次调用该合约所有带 `validCall` 的函数，包括三个强制接口，直到管理员撤销签名。
- 部署脚本已为 operator 批准了对 Pool、Oracle、SP、JP 的授权。因此 operator 现在不需要任何新签名就能调用 `forceSettle` 等接口。

### 5.2 页面上的池编号

链上池索引从 0 开始。管理后台和对客页面都显示为索引 + 1，即 pid 0 显示为"池 #1"。

### 5.3 时间校验

| 接口 | 校验 |
|---|---|
| `depositLend` / `depositBorrow` | `now < settleTime` |
| `settle` | `now > settleTime` |
| `finish` | `now > endTime` |
| `liquidate` | `now > settleTime` |

`settle` 时如果出借或抵押任一为 0，池进入 UNDONE，用户可用 `emergencyLendWithdrawal` / `emergencyBorrowWithdrawal` 取回本金。
